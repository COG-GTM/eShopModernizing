# eShop Legacy MVC Modernization - Demo Walkthrough

This walkthrough documents how Devin modernized the **eShopLegacyMVC** catalog management application from legacy .NET Framework / ASP.NET Core 2.2 on `net461` to **.NET 8**, containerized it with Docker, and added cloud-readiness features.

---

## Before State

| Area | Legacy State |
|------|-------------|
| **Target Framework** | `net461` (.NET Framework 4.6.1) |
| **ASP.NET Core** | 2.2 (end-of-life) |
| **Entity Framework** | EF Core 2.2.6 (end-of-life) |
| **DI Container** | Autofac 4.x (third-party) |
| **Logging** | log4net 2.x (third-party) |
| **Hosting** | `WebHost.CreateDefaultBuilder` + separate `Startup.cs` |
| **Serialization** | `BinaryFormatter` (security vulnerability, removed in .NET 8) |
| **Containerization** | None for this app |
| **Health Checks** | None |
| **Cloud Readiness** | Not prepared |

**Key legacy files:**
- `eShopPorted/eShopPorted.csproj` - 15 NuGet packages including Autofac, log4net, Antlr, WebGrease
- `eShopPorted/Startup.cs` - Separate startup class with Autofac container setup
- `eShopPorted/Modules/ApplicationModule.cs` - Autofac DI module
- `eShopPorted/Controllers/PicController.cs` - Referenced `System.Web.Mvc` (MVC5 namespace)
- `eShopLegacy.Utilities/eShopLegacy.Utilities.csproj` - Old-style verbose `.csproj` (49 lines)
- `eShopLegacy.Utilities/Serializing.cs` - Used `BinaryFormatter` (banned in .NET 8)

## What Devin Changed

### 1. Framework Upgrade (`net461` -> `net8.0`)

**`eShopPorted.csproj`** - Slimmed from 34 lines / 15 packages to 19 lines / 6 packages:
- Removed: Autofac, log4net, Antlr, WebGrease, Newtonsoft.Json, Microsoft.CSharp
- Removed: Individual ASP.NET Core 2.2 packages (now built into the framework)
- Updated: EF Core 2.2.6 -> 8.0.11
- Added: Health check packages for cloud readiness

**`eShopLegacy.Utilities.csproj`** - Converted from old-style (49 lines) to SDK-style (10 lines):
- Targets `net8.0` instead of `v4.6.1`
- Removed manual assembly references, compile includes, and configuration blocks

### 2. Modern Hosting Model

**Deleted `Startup.cs`** and **`Modules/ApplicationModule.cs`** - Consolidated into `Program.cs`:
- Replaced Autofac DI with built-in `IServiceCollection`
- Replaced `WebHost.CreateDefaultBuilder` + `IStartup` with `WebApplication.CreateBuilder` (minimal hosting)
- Service registration now uses `AddScoped<ICatalogService, CatalogService>()` directly

### 3. Modern Logging

**`CatalogController.cs`** and **`PicController.cs`**:
- Replaced `log4net.ILog` with built-in `ILogger<T>`
- Replaced `_log.Info(...)` with structured logging: `_logger.LogInformation("...", args)`
- Uses message templates instead of string interpolation for better log aggregation

### 4. Fixed Broken Legacy References

**`PicController.cs`**:
- Removed `System.Web.Mvc` (MVC5 namespace that doesn't exist in .NET 8)
- Fixed `HttpNotFound()` -> `NotFound()`, `HttpStatusCodeResult` -> `BadRequest()`
- Added `IWebHostEnvironment` for proper web root path resolution

**`CatalogBrand.cs`**, **`PreconfiguredData.cs`**:
- Removed `System.Web` namespace imports (doesn't exist in .NET 8)

**`Views/Shared/_Layout.cshtml`**:
- Removed reference to deleted `Startup.StartTime` static property

### 5. Security Fix

**`Serializing.cs`**:
- Replaced `BinaryFormatter` (CVE-prone, removed in .NET 8) with `System.Text.Json`
- Modernized API: added generic `Deserialize<T>()` method

### 6. Removed Obsolete Files

- `Startup.cs` - Merged into `Program.cs`
- `Modules/ApplicationModule.cs` - Autofac no longer needed
- `Views/Web.config` - Not used in modern ASP.NET Core
- `app.config` - Not used in modern ASP.NET Core
- `Properties/AssemblyInfo.cs` - Auto-generated by SDK-style projects

### 7. Containerization

**New `Dockerfile`** - Multi-stage build:
- **Build stage**: Uses `mcr.microsoft.com/dotnet/sdk:8.0` to restore, build, and publish
- **Runtime stage**: Uses slim `mcr.microsoft.com/dotnet/aspnet:8.0` image
- Includes Docker `HEALTHCHECK` instruction for container orchestrators

**New `docker-compose.yml`** - Local orchestration:
- `eshop.mvc` service with environment-based configuration
- `sql.data` service using SQL Server 2022 Linux container
- Health check dependencies ensure SQL Server is ready before app starts

### 8. Cloud Readiness

**Health check endpoints** added in `Program.cs`:
- `GET /health/live` - Liveness probe (is the process running?)
- `GET /health/ready` - Readiness probe (is the app ready to serve traffic? DB connected?)

**Environment-based configuration**:
- Connection strings configurable via environment variables (`ConnectionStrings__DefaultConnection`)
- `UseMockData` toggleable via environment for dev/staging/production

## Commands to Verify

### Build the project
```bash
cd eShopLegacyMVCSolution
dotnet build eShopPorted/eShopPorted.csproj
```

### Run locally (mock data mode)
```bash
cd eShopLegacyMVCSolution
dotnet run --project eShopPorted
# Open http://localhost:5000 in browser
```

### Run with Docker Compose (with SQL Server)
```bash
cd eShopLegacyMVCSolution
docker compose up --build
# Open http://localhost:5115 in browser
```

### Test health endpoints
```bash
curl http://localhost:5115/health/live
curl http://localhost:5115/health/ready
```

### View the Docker image size
```bash
docker images | grep eshop
```
